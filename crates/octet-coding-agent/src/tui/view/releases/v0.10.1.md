# octet 0.10.1

A Pi-compatibility fix release. octet stays a minimal native Rust agent; the
`octet-pi-compat` adapter is where Pi's surface lives, and it now follows Pi
instead of imposing Octet's own limits.

## Your Pi setup behaves like Pi

- `input`, `before_agent_start` and `session_start` handlers run until they
  settle. Pi has no timeout for them, so octet no longer skips an extension that
  takes longer than a few seconds, and no longer drops a prompt transformation or
  system-prompt replacement that arrives late.
- The transport no longer ends a prompt-phase wait on the extension's behalf.
  Cancellation, owner generations and process supervision still bound it.
- Pi 1.5 installs are accepted. The adapter resolves version-specific Pi helpers
  from your installed Pi instead of shipping its own copy.

## Fixed

- A Pi theme selected in your settings is admitted as a user-global resource
  instead of being rejected as an untrusted workspace path, so the terminal
  colours match Pi.
- Large Pi/MCP tool fleets are no longer refused by a default 128 KiB tool-schema
  quota. Complete definitions are still subject to full-request model context
  admission.
- Startup failures retain owner, instance and generation attribution with safe
  remote error codes when resource discovery is blocked after a reload. Private
  remote messages stay redacted.
- Informational theme-discovery skips no longer render as red reload failures;
  ungranted extension resource paths are still rejected.
- Compaction accepts textual summaries up to 2 MiB, including the derived file
  list, and still refuses oversized output before any checkpoint is published.

## Upgrading

Extension bundles install separately and match this binary exactly. Reinstall the
bundles you use, then start octet with `--enable-extension octet-pi-compat` as
before. Nothing is written to your Pi directory.
