# octet 0.9.0

This is an **unreleased source candidate**. There is no `v0.9.0` tag, GitHub
release, npm package or Homebrew formula. The last published native release
stays 0.8.2; the installation guide keeps pointing at it until an approved
promotion. Everything below describes source scope assembled for the 0.9.0
candidate and the qualification it has actually received, not publication.

## Highlights

- **Pi 1.0.2 compatibility push.** The optional `octet-pi-compat` adapter stays
  pinned to exactly Pi 1.0.2. Extension command argument completions now
  register natively and appear in the composer's slash UI, ordered hook
  cancellation follows real callback settlement, and session replacement
  sequences parent linkage and writable setup against the new session.
- **Interactive session correctness.** Model changes and reasoning-level
  changes queue visibly while a run is active and apply at the next safe
  request boundary; partial imports had previously been refused or gated
  without a visible queue.
- **Themes, selection and clipboard.** Every built-in theme the picker and CLI
  advertise is selectable by name (`/theme Still`, `/theme Cards`, case
  variants), and app-owned pointer selection copies the painted transcript row
  across scroll, wrap and chrome.
- **Python extension setup finishes.** `/extensions setup` activates the
  extension that failed cold start once its runtime is provisioned, without a
  restart; normal discovery still never downloads.
- **Pi setup mirroring.** Enabling the reviewed adapter discovers the user's
  Pi 1.0.2 setup read-only and activates the equivalent in Octet — extensions,
  packages, skills, prompt templates, themes, keybindings and models — and
  disabling it returns exactly to the Octet-only setup with no Pi residue.
- **Release engineering.** A one-command real-binary E2E regression suite
  (`scripts/e2e/run.sh`) drives resume, long-session scroll, selection/copy,
  themes, busy slash commands, steering, follow-up, streaming typing latency
  and Pi compat on/off against a published binary with a loopback mock
  provider. The linux x86_64 packaging path was exercised locally, including a
  byte-identical repeat of the release archive.

## Added

- `scripts/e2e/` real-binary end-to-end regression suite: disposable PTY
  sessions with a VT screen model, SGR mouse and OSC 52 clipboard readback, and
  a scripted OpenAI-compatible mock provider. One command prints PASS/FAIL per
  check, and the Pi compat smoke loads three real packages (`pi-ding`,
  `pi-powerline-footer`, `pi-hermes-memory`) from the extension matrix.
- Extension command argument completions in the composer (native registration
  plus adapter wiring), with a bounded async provider that never blocks typing.
- `docs/releases/v0.9.0.md` and the package-local copy the TUI `/changelog`
  bundles.

## Changed

- The workspace, crate pins, first-party bundle manifests, SDK distribution
  versions, the checked-in installer and the release tests move to 0.9.0.
- Release notes and installation guidance keep the candidate source version and
  the published native release distinct.
- Model and thinking controls submitted while a run is active show a visible
  queue instead of a silent refusal; theme changes keep applying immediately.

## Fixed

- Pi ordered-hook cancellation: the adapter's ordered queue and concurrency
  accounting follow the real callback settlement, so a second ordered callback
  can no longer run concurrently with a cancelled one.
- Pi session replacement (`ctx.newSession`, `ctx.switchSession`, fork) now
  commits parent linkage and writable setup against the replacement session
  instead of the closed one.
- `/theme <built-in name>` shares the picker/CLI resolver, so valid built-ins
  are no longer rejected as invalid.
- App-owned pointer hit testing aligns with the rendered viewport, so a drag
  copies the row the reader sees rather than an adjacent row.
- The native linux packager no longer demands that tracked private workstation
  records (`docs/rc/…`) appear in the public documentation inventory.
- The inherited checkpoint failures are repaired: extension hook/lifecycle
  delivery, the MCP bridge host-access replay check, Pi session replacement,
  activity/steering PTY contracts, headless before-prompt tool snapshots and the
  API 0.1 conformance wire, plus the inherited clippy lint debt.

## Known gaps in this candidate

- **Not qualified as a release.** No macOS or Windows binary has been built or
  smoke-tested for this candidate on this machine; the release workflow builds
  `x86_64-unknown-linux-gnu` on ubuntu-22.04 with Rust 1.97.1, and the two
  Apple targets on macOS runners. Only the linux x86_64 packaging path was
  exercised locally, and only as a dry run without signing or publication.
- **The large-history session transport is not in this candidate.** The U1
  session-repair.v2 integration was reverted on the release branch; sessions
  keep the legacy mirror behaviour until a reviewed replacement lands.
  Remaining large-history qualification therefore does not apply to 0.9.0.
- **Pi parity is not established.** The reviewed adapter loads a bounded set of
  real factories; arbitrary third-party extensions, private Pi internals and
  the Pi CLI are not targets. The extension matrix records packages that still
  fail and their exact errors.
- **Physical presentation is not measured.** The E2E suite observes the
  terminal buffer, mouse wire coordinates and OSC 52 payloads; it makes no
  claim about GPU frame presentation or end-to-end display latency.
- **Live provider and audio acceptance is not run.** The suite uses a loopback
  mock provider; no paid provider, subscription or live model is exercised.
- **Deeper compatibility surfaces remain unqualified**: exact tool-execution
  boundary parity, native-to-Pi live theme synchronization, and full
  presentation qualification for remote Pi components.
