# octet 0.8.0

## Fixed

- Keep `/goal` and inspection/picker slash commands responsive during streaming.
- Keep startup silent and editable, with model-context notices deferred until terminal teardown.
- Give activity shimmer a visible luminance sweep and preceding dot pulse, with a complete sweep/rest phase and neutral model identities.
- Display plain-dollar footer costs without weakening durable usage uncertainty or budget accounting.
- Settle completed workers once into their owning transcript block, without replay on later turns or displacement of scrolled history.
- Render the live subagent roster in exactly one place. The duplicate pinned chrome strip is deleted; an active roster stays in the mutable transcript tail and updates in place while the reader scrolls back; its marker dot pulses while any child is live and resolves to success, failure or stopped when the roster settles. Worker model ids print in full (a mandatory, never-ellipsized column), and the `/subagents` picker header is the stable surface name `Subagents`, not a live count.
- Remove the `completed with warnings` state from the TUI: both completed variants render the same `✓ completed · <duration> · <rate> tok/s` line, and per-call tool failures stay in their own blocks. A completed turn with live workers gets one subdued line: `subagents are running; inspect them in the /subagents menu.`
- Add the hidden `/debug` command (exact name only; never listed in the popup or `/help`): it writes an owner-private `~/.octet/octet-debug.log` with the terminal size, every rendered line and its visible width, and the agent messages as JSONL, then reports the path.
- Add `/session`: file, id, title, head, entry and active-branch message counts, checkpoints, usage records, the token buckets and exact cost, with unknown exposure explicitly marked as a known subtotal.
- Repair host-budgeted WebSocket retries, delegated usage reconciliation, ephemeral multi-session accounting recovery, and read-only delegated Serve export.
- Honour documented input modalities and context/output limits for models whose provider publishes a sparse model list, starting with DeepSeek V4.1 Flash (images now attach, and the window is its 1M/384K record instead of the generic 128K/64K placeholder); an endpoint that asserts its own metadata is never overridden.

- Reserve bounded headroom so a request never fills the model's context window exactly, and recover a provider size rejection by compacting once and retrying instead of failing the turn.

- Restore the complete `/model` provider list after a launch pinned a built-in model; startup narrowing no longer hides other configured providers from the picker.

- Read reasoning support from a provider's advertised request parameters so a newly released model gets its thinking levels without a rebuild, and name the reasoning-only failure explicitly.

- Withdraw `/tree` and `/checkout`, and rename `/quit` to `/exit`.

- Ease the activity shimmer's resting colours off pure white and pure black so the Working/Thinking indicators read a step closer to grey. The light bound is measured, not chosen: a 0.009 rest fails the pinned 1.7:1 worst-case cell separation for a blue identity after ANSI256 quantization, so the light rest is 0.0085 and the light sweep ceiling moves 0.09 -> 0.095 to preserve the pinned 0.08 relative-luminance travel.

## Changed

- Add `/settings` (defaults, theme, images and default model/reasoning; transport and editor padding stay read-only facts) and `/scoped-models` (ordered Ctrl+P scope persisted as the user `models` key), plus `!command`/`!!command` local shell escapes that record included or explicitly excluded context.
- Add `--powershell` (additive Windows tool opt-in, inert elsewhere) and ordered `--models` patterns that resolve literal references first and keep each `:level` reasoning suffix.
- Add live, capability-gated `/fast` priority selection, queued safely during active work, with durable conservative cost uncertainty.
- Consume user keybindings and scoped model cycling; preserve drafts when shortcuts generate commands.
- Add bounded rich Markdown/syntax HTML export, explicit local-model evaluation profiles, session-backed tool checkpoints/memos, and host-accounted summary retries.
- Add a session-isolated negotiated API 0.3 process event bus; this does not grant arbitrary Pi UI or cross-session authority.
- Add **live reload**: the interactive prompt watches the skill, prompt, theme, context-file, keybinding, settings and extension roots in use plus the resolved executable, and applies a pass only at an idle prompt in the fixed order resources → extensions → host (1000 ms metadata poll, 200 ms debounce with a 2 s ceiling). It is enabled by default for the interactive prompt and announces itself once; `reload`, `reload_poll_ms`, `reload_debounce_ms` and `reload_max_files` are user-level settings, `/reload --dry-run` previews a pass and `/reload --force` takes one while naming what it will lose. When the binary on disk changed, `/reload` validates the candidate with a side-effect-free probe and **re-execs the host**: same PID, same session resumed, extension children stopped through the bounded path, session locks released, nothing locked on the executable — several panes reload independently. Live delegated workers are detached on request and reattached afterwards. Late `providers/register`, `providers/update` and `providers/unregister` take effect in a running session without a reload, matching Pi, with credentials and authority staying host-owned.
  **P0 dogfood cut (post-review correction):** host re-exec is no longer armed by the generic live-reload default. Plain `/reload` is resources/extensions only; the host layer requires `/reload --force` or the explicit user-level `reload_host = true`. A moved or replaced binary (retargeted symlink, new inode) is never probed — the probe is the candidate's first execution — until the user confirms, and the descriptor sweep enumerates `/dev/fd` (or `/proc/self/fd`) instead of stopping at a fixed numeric cap, failing closed when it cannot list every descriptor. Unknown-outcome deferred polls likewise need an explicit replacement resume instead of a second automatic billable poll.
- Identify the local Rust build and its first-party Cargo dependencies as 0.8.0.
- Include the reviewed additive provider, codec, tool, editor, CLI and rendering work. The detailed parity ledger distinguishes tested behavior from incomplete primitives.

## Known limits

Pi parity is not complete. Product open-all remains fail-closed until atomic writer claim/settlement exists. `/fast` is process/current-session scoped, does not promise provider acceptance, and retains uncertainty after disabling; real extension theme/UI consumers and broader provider/bridge parity remain incomplete. Formatting, native/live qualification and other gaps remain recorded in `docs/parity/DELIVERY.md`.

Live reload is bounded on purpose, and these are its limits: a **model call in flight** is lost when a forced pass crosses it (the record survives and is not replayed); an extension's in-flight host request is fenced by its restart; a worker mid-call loses that call while its durable record, accounting and approval state are preserved and reattached; a running `octet serve` is unaffected by a pane reloading but does **not** pick up a new binary itself until it is restarted; and a process-boundary reattach in the extension-only delegation configuration remains unproven (the native-tools configuration is covered).
