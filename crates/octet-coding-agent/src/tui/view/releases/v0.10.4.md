# octet 0.10.4

Your Pi setup, closer to how it works in Pi, and one guided command to bring it
over. This is an unreleased source candidate until published. Publication
and asset availability must be confirmed on the
[version-pinned release page](https://github.com/skaft-software/octet/releases/tag/v0.10.4).

## New

- `octet migrate pi` brings your Pi setup over in one step: a short overview of
  what it found, what turning it on does, and one question. Yes installs the Pi
  adapter and turns it on, backing up octet's config first; Pi's settings are
  never written. `--dry-run` previews, `--undo` turns it off again.

## Changed

- pi-subagents loads like any other Pi package, so its commands work.
- With the Pi adapter on, octet says in one line when its model differs from
  your Pi default model (switch with `/model`).

## Fixed

- Resuming a session with thousands of messages no longer stalls Pi extension
  startup: an unchanged history is not re-sent on every screen refresh.
- A slash command entered once during startup runs when octet is ready.
- On Unix, `/reload --force` restarts the app from disk and resumes your session,
  even when the binary is unchanged. Blocking subagents are detached with their
  sessions kept; binary compatibility and durable-session checks still apply.
- Pi permission and compaction hooks can inspect mixed-model reasoning history.
  Throwing compaction callbacks warn and continue without bypassing explicit vetoes.
- Pi adapter cache writes no longer cause repeated startup hooks and footer resets.
- `octet update` on Windows updates a release ZIP unpacked outside the default
  folder, and its errors keep their line breaks.
- octet-codemode started from source no longer reuses an old cached build.
- Pi session browsers such as `/sessions` point you at `/resume` instead of
  failing, and extension startup failures read in plain words.
- More unchanged Pi examples behave as in Pi, Pi footers opened at startup stay
  mounted, and extension-registered providers stream.

## Compatibility

Pi extension API 0.4 bundles are pinned to this host: run
`octet extension update <name>` for each bundle after updating.
