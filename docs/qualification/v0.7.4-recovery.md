# v0.7.4 recovery: source contract and qualification boundary

**Historical v0.7.4 qualification record; not a Codex-parity, issue-closure, or
endurance claim.** v0.7.4 was published on 2026-09-11 after protected CI and
signed installation checks. See the [release record](../releases/v0.7.4.md) for
those results and the subsequently reported SSH model-switch regression.
Local candidate hashes below are not the signed release artifacts.
This note separates the in-process recovery contract from the unattended-running
acceptance target in [#350](https://github.com/skaft-software/octet/issues/350).
The [latest incident update](https://github.com/skaft-software/octet/issues/350#issuecomment-5634356457)
and [minimal-shape correction](https://github.com/skaft-software/octet/issues/350#issuecomment-5620397080)
remain applicable. Whole-run duration is not physical-request duration; the
reported disconnects do not establish a network/provider root cause.

## Released source contract

The acceptance target is at least equivalent interruption resilience to the
pinned Codex implementation; matching a retry count alone does not meet it.

- Recovery surrounds an unfinished provider operation, not the whole user task.
  Host-declared Codex Responses runtime plus the local-function request shape
  qualifies ordinary inference, including Responses Lite. A model name, zero
  frames, extension advice, or arbitrary compatible endpoint does not qualify
  it. Unknown opaque input kinds, explicit remote continuation/storage/context
  management, and provider-hosted effects retain conservative treatment.
- Before assistant commit, eligible transient provider errors, header/body
  transport failures and terminal-boundary premature EOF may replace inference
  after provisional output is discarded. Arbitrary JSON/UTF-8 decoding, schema,
  pricing, resource-limit, and validation errors are not blanket retry triggers.
  Completed assistant/tool results remain durable; failed assistant persistence
  is not crossed by the replacement loop. Streamed tool envelopes have not yet
  executed, including proposed mutations.
- The released source separates eleven streamed-inference replacements from
  twenty-nine qualified HTTP-admission replacements, under a shared cap of
  thirty-five replacements. This does not reproduce Codex’s nested retry
  semantics or prove thirty-six accepted generations/charges. Deterministic
  tests cover the finite budgets; live mixed-failure endurance is not established. Finite budgets
  are not replenished by opening a socket, receiving a token, re-preparing
  context, or switching transport. Unknown failed-attempt usage is **not zero**. Hard
  cumulative cost/token ceilings fail closed when that exposure cannot be
  bounded; ordinary successful-response accounting is not an outstanding-spend
  reservation. Socket retirement proves neither remote cancellation nor
  exactly-once inference or billing. HTTP 5xx, particularly a gateway 504, does
  not prove zero usage: uncertainty is persisted before replacement, and hard
  cumulative ceilings stop at the first ambiguous status. This applies to
  auxiliary/manual operations as well as main sampling.
- Positively classified pre-send `AiError::NetworkUnavailable` and credential
  `AuthError::Unavailable` may instead enter sustained, cancellable waiting on
  qualified requests, without consuming the finite inference budget. Backoff
  starts from five seconds, doubles with run-specific jitter and caps at sixty
  seconds. Generic DNS/TLS/certificate/configuration errors do not establish
  this classification. Valid provider `Retry-After` is not shortened to thirty
  seconds. No arbitrary internet probe or independent OAuth retry loop is added;
  accepted/ambiguous token rotation remains conservative.
- Fatal WebSocket state is retired/disabled before error publication. A permitted
  immediate replacement can use preferred-transport HTTP fallback; fallback is
  not independent permission to replay accepted work. Ping/Pong liveness does
  not extend the provider-progress deadline, and zero frames do not prove that
  inference was never accepted.
- The main loop re-enters safe request preparation, preserving accepted controls,
  steering/follow-up scheduling, and `finish_now` tool suppression. Waiting is
  not run settlement or child shutdown. Explicit cancellation remains terminal.
  Recovery status is transient: the interactive view removes failed-attempt
  reasoning/text/media, including reasoning closed before public text, while
  retaining unrelated activity. Correct native-history removal may require a
  replay; quiet status does not promise zero scrollback repaint.
- `ProviderRetry` invalidates provisional main-answer output. The additive
  `ProviderWaitingForNetwork` carries no finite denominator. Auxiliary recovery
  has a separate operation-scoped `ProviderOperationRetry`; it must not discard
  an unrelated main answer. Host/RPC casing and extension advice are documented
  in [SDK](../sdk.md#event-lifecycle) and
  [extensions](../extensions.md#provider-retry-observations-and-advice).
  Native-host/extension API and session schema versions are not bumped; the
  session record contract nevertheless evolves with additive `usage_uncertainty`.
- Unknown accepted-attempt usage is durably appended separately from the known
  subtotal before replacement. `Session::has_uncertain_usage()` remains true
  across success, resume, checkout, and compaction; fork accounting is independent.
  `ProviderUsageUncertain` is a unit event; native host emits empty `data` and
  CLI RPC emits the event type alone. Later numeric costs/tokens are known
  subtotals, not complete totals. UI and plain/print warn; Serve completion review
  retains the warning. RPC `get_state`/statistics now expose `usageUncertain`,
  including idle/resumed state; statistics use the independent durable usage
  ledger. Native host has no idle session-inspection command; resumed runs
  emit the live warning. Consumer checks are recorded below.

## Pinned Codex comparison, not parity certification

Read-only source comparison used local `openai/codex` at
`3d3df0a0cad5d3d8d3340b633787e9dd304ea463`:

- `codex-rs/core/src/responses_retry.rs:58-128` separates eligible sampling
  connection outages (5s-to-60s waits, excluding internal sessions and Bedrock)
  from finite stream retries, with a one-time WebSocket-to-HTTPS transition and
  stream-budget reset on that transition.
- `codex-rs/model-provider-info/src/lib.rs:30-31,416-425` defaults ordinary
  stream retries to five and HTTP request retries to four.
  `codex-rs/codex-client/src/retry.rs:80-108` performs up to five physical HTTP
  sends per outer invocation. Six outer HTTP sampling invocations can therefore
  yield thirty POST attempts, or conditionally thirty-six physical attempts
  with six preceding WebSocket attempts—not twelve total physical attempts.
  These are attempts, not confirmed accepted generations or charges.
- `codex-rs/codex-api/src/api_bridge.rs:76-86,131-132,169-183` maps HTTP failures
  into distinct overload/internal-server/unexpected-status errors; retryability
  depends on both layers and classification. `server_error` is not evidence of
  an unbounded outage policy, and HTTP 5xx is not proof of zero provider usage.
- `codex-rs/core/src/session/turn.rs:1445-1522` rebuilds sampling input from
  retained history. `codex-rs/core/src/client.rs:2080-2096` makes fallback sticky
  and clears WebSocket session state.

These are comparison points, not a promise of identical classifiers, budgets,
transport transitions, tool dispatch, UI, or failure accounting. octet's active
15s Ping / 10s acknowledgement gate is not established as inherited Codex
behavior. No Codex tests were run for this documentation update.

## User-reported live check

The user reports switching Wi-Fi networks mid-run: v0.7.3 stopped on a Responses
WebSocket heartbeat acknowledgement timeout, while the provisional v0.7.4 build
continued gracefully. Manual compaction also worked; its partial-label shimmer
was reported separately and corrected in source. This is user-observed live
recovery evidence, not a controlled parity experiment or endurance run. The
exact binary hash, terminal matrix, and repeated fault schedule were not recorded;
this report alone does not close #382 or the remaining qualification gates.

## Remaining qualification

Deterministic and PTY tests qualify their tested paths, not every deployed
network or terminal. The shipped source includes the outage setter and inherited
child bound, main/local/native/terminal-gate recovery, operation-scoped hooks,
durable uncertainty and consumer accounting. The final opening-deadline fix was
tested locally and included in the green frozen-source CI.

Remaining limits:

- Controlled repeated live interruption/recovery, full Codex parity and actual
  weeks-scale soak duration are not established. Removing a retry ceiling is
  not endurance evidence.
- Maintainer-reported terminal acceptance preceded publication, but a subsequent
  Ghostty-to-SSH model-switch report exposed stale splash rows. Later fixes need
  their own targeted physical evidence; the earlier acceptance cannot qualify
  that journey on their behalf.
- Durable uncertainty is not outstanding-spend reservation or remote billing
  reconciliation. Process-death recovery, heartbeat backpressure, parser defects
  and session-ledger capacity are not silently solved by in-process replacement.
