# Experimental Anthropic cache-warming building block (not shipped)

**Not an end-to-end Octet feature:** no coding-agent idle scheduler, CLI mode, or extension hook invokes this library API. A host explicitly calling `Agent::warm_prompt_cache(CacheWarmMode::Idle, CacheWarmPolicy::default()).await` at a settled idle boundary makes **at most one** additional inference request; `Off` is inert. No streaming mode is implemented. This is not a guaranteed cache hit or a free operation.

Eligibility requires the built-in direct Anthropic Messages route (`anthropic`, `https://api.anthropic.com/v1/`, HTTP), short retention, reasoning off, a priced completed assistant response on the active branch, a settled assistant tail ending in nonempty text that can carry a cache breakpoint, an estimated prompt of at least 4,096 tokens, and at least four minutes since the most recent assistant response/complete warm. Gateways, long retention, unpriced or uncertain sessions, oversized requests and requests exceeding configured session limits skip or refuse the request. The default policy bounds one wall-clock attempt to 30 seconds, a conservative $0.05 per-attempt reservation, $0.20 of known cumulative warm spend and six attempts per session. Hosts must explicitly schedule calls; these thresholds do not automatically refresh a cache.

The request uses the current canonical context, system/tool schema and a synthetic final user instruction, one output token and no local tool execution. Its synthetic instruction and generated output are discarded, **not** added to the conversation. For this one-off warm request, the Anthropic codec puts the ephemeral message breakpoint on the last canonical assistant block, **before** the synthetic suffix; a normal follow-up instead marks its final real user block. The warmed canonical prefix is therefore reusable when the schema/reasoning context matches, though a hit is not guaranteed. The feature is intentionally best-effort; no live Anthropic cache-hit/cost qualification has been performed.

The session stores separate `cache_warm` lifecycle records (`started`, `completed`, `timed_out`, `failed`) and `usage` with `kind: cache_warm` on a complete response. Provider-reported input, cache-read, cache-write, output and exact known cost count toward session totals, never assistant-turn cache metrics. A deadline or failure after possible dispatch records usage uncertainty rather than an invented zero. A crash after `started` and before settlement remains uncertain on reopen and blocks hard session ceilings. No raw prompt, generated output, provider error, URL or credentials appear in lifecycle records. There is no retry.

Limitations: this library API is not yet wired to coding-agent idle scheduling, commands/status UI or executable-extension lifecycle hooks; those require integration outside `octet-agent`. The request is an extra billable provider call even if it yields a cache hit. For remote failures, the exact provider charge cannot be known. Live endpoint behavior, prompt-prefix reuse and pricing have not been verified.
