# octet 0.10.0 — Pi compatible

**octet's first Pi-compatible release.** Bring your Pi extensions, skills,
prompt templates, themes and custom UI to a native, open-source coding agent.
This is an experimental release for the community to use, extend and improve.

## Get started

Install octet and enable the optional Pi adapter using the
[Pi setup guide](../pi-compatibility.md). The
[versioned release page](https://github.com/skaft-software/octet/releases/tag/v0.10.0)
records available downloads and checksums. Optional extension bundles install
separately; installing or discovering one does not execute it.

Pi support targets **Pi 1.0.2's public extension API**, with Node 22.19+ running
the extension process. Rust owns the agent loop, sessions, permissions and
terminal. Ordinary octet use and the native codemode extension do not need Node.

## What's new

- **Bring your Pi setup.** Import installed extensions, skills, prompts and
  themes, or select factories manually. Pi joins codemode, computer use, MCP,
  subagents and web search in the six-bundle extension catalog.
- **Native extension commands.** Command catalogs and resource provenance come
  from the live native host, including across reloads. Metadata does not grant
  execution authority.
- **Reliable startup facts and tools.** Interactive startup publishes real
  model/scoped-model facts before extension callbacks. Late tool registration
  can receive its catalog acknowledgement without deadlocking its own startup
  callback. CamelCase tools such as `mcpScript` retain their exact identity in
  activation, selection, exclusion and execution.
- **Editor and footer integration.** Applied theme writes no longer trigger
  redundant reloads that retire composed Pi mounts. Legacy raw `0x1f` input
  matches Pi's Ctrl+- undo; explicit Kitty Ctrl+7 remains distinct.
- **Command context.** Admitted commands read the native system prompt rather
  than depending on a missing cached snapshot. App-deferred headless startup
  receives refreshed, credential-filtered model facts.
- **Recoverable Windows extension updates.** Validated replacements use locked
  recovery; failures restore the previous bundle or retain a recovery backup.
  Linux and macOS retain atomic exchange.

Tool selectors are now case-sensitive, including builtin names: use `read`, not
`Read`. This preserves the exact identities of extension tools.

## Trust and permissions

Enabling the stock Pi adapter imports and runs your enabled Pi factories with
your OS permissions. **It is not a sandbox.** Provider-credential disclosure
requires a separate reviewed opt-in. Native owner, generation, admission and
reload fences remain authoritative.

## Known boundaries

- See the [API ledger](../pi-extension-api.md) for individual API coverage and
  known gaps. Pi's private internals and complete CLI are not the compatibility
  target. Bring a reproducible extension example when reporting a gap.
- Windows remains preview; GNU tests do not establish native MSVC, physical
  console or desktop-driver acceptance. Bun is not qualified; use Node 22.19+.
- Live provider/audio and model-quality acceptance are not part of this launch's
  qualification. No whole-release performance claim is made.
- Python-backed optional adapters need Python 3.11+ with `venv`/`ensurepip`, or
  an explicitly configured private runtime. Codemode needs neither Python nor Node.

Found a rough edge? [Open an issue](https://github.com/skaft-software/octet/issues)
with your octet version, platform, extension and reproduction steps. Contributions
