# octet 0.8.0

**Local release candidate — not published.** The product direction is a fast,
small, model-flexible coding agent. Extensions add tools and bounded host-shaped integrations, not Pi parity
or an everything-as-extension platform. Serve, Browse, MCP, subagents, web search,
and retained protocol safety/conformance remain in scope.

## Fixed

- Keep `/goal` and inspection/picker slash commands responsive during streaming.
- Keep startup silent and editable, with model-context notices deferred until terminal teardown.
- Give activity shimmer a visible luminance sweep and preceding dot pulse, with a complete sweep/rest phase and neutral model identities.
- Display plain-dollar footer costs without weakening durable usage uncertainty or budget accounting.
- Hide the root elapsed clock throughout retry status, including after the countdown expires, while retaining the interrupt hint; normal Working/Thinking elapsed clocks are unchanged.
- Settle completed workers once into their owning transcript block, without replay on later turns.
- Render subagent activity as a single tool-like transcript-tail block: its bold count heading has up to four indented live worker lines with task, current tool/phase and latest reported tokens, plus an overflow count. Its marker pulses while workers run, follows new parent output, and settles with outcome colour and no child lines. Full worker details remain in `/subagents`; restart hydration restores bounded orchestration activity without exposing call arguments or treating a successful spawn as child completion.
- Remove the `completed with warnings` state from the TUI: both completed variants render the same `✓ completed · <duration> · <rate> tok/s` line, and per-call tool failures stay in their own blocks. A completed turn with live workers gets one subdued line: `subagents are running; inspect them in the /subagents menu.`
- Add the hidden `/debug` command (exact name only; never listed in the popup or `/help`): it writes an owner-private `~/.octet/octet-debug.log` with the terminal size, every rendered line and its visible width, and the agent messages as JSONL, then reports the path.
- Add `/session`: file, id, title, head, entry and active-branch message counts, checkpoints, usage records, the token buckets and exact cost, with unknown exposure explicitly marked as a known subtotal.
- Repair host-budgeted WebSocket retries, delegated usage reconciliation, ephemeral multi-session accounting recovery, and read-only delegated Serve export.
- Honour documented input modalities and context/output limits for models whose provider publishes a sparse model list, starting with DeepSeek V4.1 Flash (images now attach, and the window is its 1M/384K record instead of the generic 128K/64K placeholder); an endpoint that asserts its own metadata is never overridden.

- Reserve bounded headroom so a request never fills the model's context window exactly, and recover a provider size rejection by compacting once and retrying instead of failing the turn.

- Restore the complete `/model` provider list after a launch pinned a built-in model; startup narrowing no longer hides other configured providers from the picker.

- Read reasoning support from a provider's advertised request parameters so a newly released model gets its thinking levels without a rebuild, and name the reasoning-only failure explicitly.

- Withdraw `/tree` and `/checkout`, and rename `/quit` to `/exit`.

- Ease the activity shimmer's resting colours off pure white and pure black so the Working/Thinking indicators read a step closer to grey. The light bound is measured, not chosen: a 0.009 rest fails the pinned 1.7:1 worst-case cell separation for a blue identity after ANSI256 quantization, so the light rest is 0.0085 and the light sweep ceiling moves 0.09 -> 0.095 to preserve the pinned 0.08 relative-luminance travel.

## Changed

- Keep model/thinking/subagent inspection and tool-consent surfaces inside the active run loop instead of suspending caller-driven inference. Renderer-owned layout and terminal writes no longer hold the semantic input lock; emitted-frame feedback is revision-fenced.
- Bound Bash spills to 64 MiB / 32 files per owner (including active captures), with oldest-first expiry and off-path disk work; retain the 16 MiB per-stream cap. Bound undo and redo to 64 snapshots / 4 MiB each.
- Advance route-affine Responses replay and capacity projections incrementally; reserve accepted run controls through delivery; cap combined extension schemas; use indexed session search and batched maintenance beyond the former 64 MiB catalog limit. Optional telemetry writes use a bounded ordered worker with observable loss/failure and bounded lifecycle drain. These are structural improvements, not end-to-end latency or constant-memory guarantees.

- Add `/settings` (defaults, theme, images and default model/reasoning; transport and editor padding stay read-only facts) and `/scoped-models` (ordered Ctrl+P scope persisted as the user `models` key), plus `!command`/`!!command` local shell escapes that record included or explicitly excluded context.
- Add `--powershell` (additive Windows tool opt-in, inert elsewhere) and ordered `--models` patterns that resolve literal references first and keep each `:level` reasoning suffix.
- Add live, capability-gated `/fast` priority selection, queued safely during active work, with durable conservative cost uncertainty.
- Consume user keybindings and scoped model cycling; preserve drafts when shortcuts generate commands.
- Add bounded rich Markdown/syntax HTML export, explicit local-model evaluation profiles, session-backed tool checkpoints/memos, and host-accounted summary retries.
- Add a session-isolated negotiated API 0.3 process event bus; this does not grant arbitrary Pi UI or cross-session authority.
- Add **live reload**: the interactive prompt watches the skill, prompt, theme, context-file, keybinding, settings and extension roots in use plus the resolved executable, and applies a pass only at an idle prompt with host eligibility/consent checked before resource and extension rebuilding; an admitted host replacement supersedes those rebuilds (1000 ms metadata poll, 200 ms debounce with a 2 s ceiling). It is enabled silently by default for the interactive prompt; `reload`, `reload_poll_ms`, `reload_debounce_ms` and `reload_max_files` are user-level settings, `/reload --dry-run` previews a pass and `/reload --force` takes one while warning of potential losses. When the binary on disk changed, `/reload` validates the candidate with a side-effect-free probe and **re-execs the host**: same PID, same session resumed, extension children stopped through the bounded path, session locks released, nothing locked on the executable — several panes reload independently. Live delegated workers are detached on request and reattached afterwards. Late `providers/register`, `providers/update` and `providers/unregister` take effect in a running session without a reload, with credentials and authority staying host-owned.
  **P0 dogfood cut (post-review correction):** host re-exec is no longer armed by the generic live-reload default. Plain `/reload` is resources/extensions only; the host layer requires `/reload --force` or the explicit user-level `reload_host = true`. Automatic passes omit success summaries and report host, worker-deferral, extension, provider-catalog, and watch-limit problems once per component/condition, repeating them after a successful check clears the condition; skipped components retain their diagnostics. Resource/bootstrap and keybinding checks use the same checked-component recurrence rule; explicit commands still report diagnostics. Actual work losses are always reported. Automatic permission paths never open a picker or probe an unconsented replacement; explicit reload retains its consent flow. A moved or replaced binary (retargeted symlink, new inode) is never probed — the probe is the candidate's first execution — until the user confirms, and the descriptor sweep enumerates `/dev/fd` (or `/proc/self/fd`) instead of stopping at a fixed numeric cap, failing closed when it cannot list every descriptor. Unknown-outcome deferred polls likewise need an explicit replacement resume instead of a second automatic billable poll.
- Identify the local Rust build and its first-party Cargo dependencies as 0.8.0.
- Retain provider, codec, tool, editor, CLI and rendering work under its documented limits. Historical comparison ledgers retain evidence, not release obligations.
- Remove the Pi extension-execution bridge and its CLI entrypoint; keep Pi inventory, portable import/restore, and native provider support separate.

## Known limits

Pi extension execution/parity is not supported or a release goal. Product open-all remains fail-closed until atomic writer claim/settlement exists. `/fast` is process/current-session scoped, does not promise provider acceptance, and retains uncertainty after disabling. A low-level extension method does not establish a product UI or host-service guarantee. Historical tests and gaps remain in `docs/parity/DELIVERY.md`; current gates are selected by the roadmap. Compacting live worker lines after their row has scrolled above the viewport can rebuild saved terminal scrollback to remove stale previews.

Live reload is bounded on purpose, and these are its limits: passes apply only at the idle boundary, never across a root model/tool call; forced-pass interruption previews reflect current pending host requests and workers; extension host-request losses are counted and named only when requests are actually discarded, not merely because a forced-pass warning listed that risk; a worker mid-call loses that call while its durable record, accounting and approval state are preserved and reattached; a running `octet serve` is unaffected by a pane reloading but does **not** pick up a new binary itself until it is restarted; and a process-boundary reattach in the extension-only delegation configuration remains unproven (the native-tools configuration is covered).
