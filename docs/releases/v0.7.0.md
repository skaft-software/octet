# octet 0.7.0 — unreleased

**Unpublished and not release-qualified.** These notes describe the implemented
0.7.0 source candidate. Final release CI, optimized platform/package installation,
and deterministic media/recovery acceptance remain separate gates. Live-provider
and native-audio checks are optional and **not run** for this candidate. Local
tests and the website's illustrative TUI recreation are not live demonstrations.

Use the [local checkout build](../../README.md#install) while the release is
unpublished. The source and release repository remains
[skaft-software/ygg](https://github.com/skaft-software/ygg). See
[distribution channels](../distribution.md) for the planned native, npm and
Git-tag Cargo installation paths; crates.io publication is not part of the
current release workflows. Bun remains unqualified.

## Added

- Native Google Gemini/Vertex and Amazon Bedrock integrations, Azure OpenAI
  support, and additional Mistral/Cloudflare provider declarations. Provider
  routes and supported subsets are explicit; declared routes do not establish
  live-service or complete Pi-provider acceptance.
- Transactional custom-provider onboarding and opt-in cold-start feedback for
  endpoints that implement the corresponding readiness contract.
- A reusable terminal text editor and improved ordinary command/picker surfaces.
  `--show-images` opts in to bounded tool-result images on compatible interactive
  terminals; it is off by default and does not grant upload consent.
- Extension API 0.3's schema-generated foundation, trusted manifest CLI flags,
  declared session hooks and host-owned lifecycle services where offered. The
  [extension guide](../extensions.md) distinguishes these from legacy methods.
- Selective Pi setup import with preview, private backups and restore, plus pinned
  local compatibility plans and wrappers. These are bounded capabilities, not
  whole-setup migration or universal Pi source/UX parity.
- Topic-based repository documentation, usage examples and the
  [Brand Kit](../assets/octet/README.md). The public website is prepared separately
  from the product's release and installation channels.

## Changed

- Adopted the lowercase octet name, `octet` and `octet-host` binaries,
  `octet-*` packages, `OCTET_*` settings and `.octet` directories. Packaged
  documentation uses `share/octet`.
- Thinking choices now retain endpoint-specific exact values, gaps, defaults,
  binary controls and always-on behavior. Explicit false and manual metadata
  remain authoritative; malformed assertions fail closed. Genuine provider model
  labels are preserved without fabricating overrides from raw IDs.
- Ultra requires explicit provider support and V2 delegation; the coding product
  additionally requires its trusted, enabled observing subagents extension.
  Responses encodes supported Ultra as `max`, not an arbitrary universal effort.

See [package identities](../distribution.md#package-identities) and
[provider thinking](../provider-thinking.md) for the precise source contracts.

### Existing Ygg installations

**Install octet afresh. `ygg update` is not a supported octet upgrade path.**
Existing Ygg installations and data remain separate and untouched. There are no
old command or `YGG_*` aliases, `.ygg` fallbacks, automatic folder merges, or
Hamr/Ygg credential and package-hotfix imports. Back up existing data before
removing an old installation; do not assume a new octet installation discovers
old sessions or settings. Scripts and custom extensions using old first-party
names need review.

An old Ygg updater may select v0.7.0 as the latest GitHub release, then fail when
it requests the retired Ygg installer/package names. This release supplies no
transition carrier. Third-party `~/.codex/auth.json` interoperability and explicit
Pi import/restore remain separate features and do not modify their source stores.

## Fixed

- Provider-start WebSocket fallback distinguishes a safe pre-acceptance failure
  from an ambiguous request that must not be replayed automatically.
- Google replay repairs missing tool results in the documented lossy conversion.
- Typed-media validation, attachment consent, cancellation and local-compaction
  replay across persisted-session reopening are hardened.
- Native compact requests reject unsupported reasoning controls before resource
  reservation; raw compact controls are validated before credential resolution
  or network access.
- Bedrock signed/redacted reasoning continuation and Cerebras reasoning encoding
  follow their specific contracts. Opaque retained state is aggregate-bounded,
  replacement-aware and redacted in Debug output.
- Always-on exact On-only metadata is accepted without enabling Off; malformed
  nested support assertions cannot silently enable reasoning.
- Narrow terminal layouts, duplicate startup rendering and inherited terminal
  cursor margins are repaired. Active waits remain interruptible and tool/input
  visibility is preserved.

Local compaction remains the default. None of these fixes establishes current
octet benchmark results or completed live-provider acceptance.

## Extension compatibility

Current authoring documentation targets extension API 0.3. The four bundled
executable-extension manifests still declare 0.2, and the Python `Extension`
runtime remains a legacy 0.1/0.2 implementation. Generated 0.3 types and negotiation
helpers are not a complete standalone 0.3 authoring runtime or runnable example.
Native-host protocol 1 remains independent of extension API versions. See the
[extension guide](../extensions.md) and [native host reference](../sdk.md).

## Release gates

Before announcing public availability, verify final candidate CI/security checks,
release artifacts and installation on each claimed platform, channel ownership
and publication, and the exact public installer/package paths. Deterministic
media/recovery and genuine pinned Pi runtime qualification remain required.
The full Pi gate is separate from general CI. See the
[Pi compatibility boundary](../pi-migration.md#deliberate-compatibility-boundary).

Release qualification does not require live-provider credentials or paid API
calls. [Live provider/native-audio checks](../experimental/octet-serve/provider-acceptance.md#optional-credentialed-acceptance)
are separately opt-in. When not selected, the release records **NOT RUN**, not a
pass or a live-service compatibility claim.
