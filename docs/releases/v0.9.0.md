# octet 0.9.0

This is an **unreleased source candidate**. There is no `v0.9.0` tag, GitHub
release, npm package or Homebrew formula. The last published native release
stays 0.8.2; the installation guide keeps pointing at it until an approved
promotion. Everything below describes source scope assembled for the 0.9.0
candidate and the qualification it has actually received, not publication.

## Highlights

- **Pi 1.0.2 compatibility push.** The optional `octet-pi-compat` adapter stays
  pinned to exactly Pi 1.0.2 and gains fixes found by the real-extension
  matrix: tool images on the real host, `agent_settled`, nested `ctx.executeTool`
  images, provider hook reservations, module shims, cancelled ordered hooks, and
  a clean on/off toggle that leaves no Pi residue when disabled.
- **Interactive session correctness.** The composer/editor architecture gives
  the terminal one owner with a composer slot, extension editors render inside
  it, and busy Enter steering / Ctrl+S follow-up follow the native admission
  path. Model and thinking changes queue visibly at a safe boundary while theme
  changes stay immediate.
- **Large-history transport.** The approved session-repair.v2 chunked transport
  replaces the legacy 512 KiB mirror between the native host and the adapter.
- **Terminal, themes and mouse.** Built-in themes are selectable by name,
  Tern native surfaces keep their theme projection, and app-owned pointer hit
  testing aligns with the rendered viewport so selection copies the row the
  reader sees.
- **Release engineering.** A one-command real-binary E2E regression suite
  (`scripts/e2e/run.sh`) drives resume, long-session scroll, selection/copy,
  themes, busy slash commands, steering, follow-up, streaming typing latency and
  Pi compat on/off against a published binary with a loopback mock provider.

## Added

- `scripts/e2e/` real-binary end-to-end regression suite: disposable PTY
  sessions with a VT screen model, SGR mouse and OSC 52 clipboard readback, and
  a scripted OpenAI-compatible mock provider. One command prints PASS/FAIL per
  check, and the Pi compat smoke loads three real packages (`pi-ding`,
  `pi-powerline-footer`, `pi-hermes-memory`) from the extension matrix.
- `docs/releases/v0.9.0.md` and the package-local copy the TUI `/changelog`
  bundles.

## Changed

- The workspace, crate pins, first-party bundle manifests, SDK distribution
  versions, the checked-in installer and the release tests move to 0.9.0.
- Release notes and installation guidance keep the candidate source version and
  the published native release distinct.

## Fixed

- Pi ordered-hook cancellation: the adapter's ordered queue and concurrency
  accounting follow the real callback settlement, so a second ordered callback
  can no longer run concurrently with a cancelled one.

## Known gaps in this candidate

- **Not qualified as a release.** No macOS or Windows binary has been built or
  smoke-tested for this candidate on this machine; the release workflow builds
  `x86_64-unknown-linux-gnu` on ubuntu-22.04 with Rust 1.97.1, and the two
  Apple targets on macOS runners. Only the linux x86_64 packaging path was
  exercised locally, and only as a dry run without signing or publication.
- **Pi parity is not established.** The reviewed adapter loads a bounded set of
  real factories; arbitrary third-party extensions, private Pi internals and
  the Pi CLI are not targets. The matrix records packages that still fail and
  their exact errors.
- **Physical presentation is not measured.** The E2E suite observes the
  terminal buffer, mouse wire coordinates and OSC 52 payloads; it makes no
  claim about GPU frame presentation or end-to-end display latency.
- **Live provider and audio acceptance is not run.** The suite uses a loopback
  mock provider; no paid provider, subscription or live model is exercised.
- **Deeper compatibility surfaces remain unqualified**: exact tool-execution
  boundary parity, native-to-Pi live theme synchronization, and full
  presentation qualification for remote Pi components.
