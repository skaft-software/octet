# octet 0.9.0

This is an **unreleased source candidate**. There is no `v0.9.0` tag, GitHub
release, npm package or Homebrew formula; until an approved promotion, the
installation guide keeps naming the preceding 0.8.2 candidate. Everything below
describes source scope assembled for the 0.9.0 candidate and the qualification
it has actually received, not publication.

## Highlights

- **Bring your Pi setup with you.** The optional `octet-pi-compat` adapter
  imports a reviewed Pi 1.0.2 setup — extensions, packages, skills, prompt
  templates, themes, keybindings, models and the global context file — or
  mirrors it read-only at startup, and disabling it returns to the octet-only
  setup. Pi 1.0.2 extension surfaces grow with tool call/result hooks, custom
  messages, safe session replacement, command argument completions, the
  pre-native terminal input lane, imported palettes and reviewed builtin tool
  replacements.
- **Interactive session correctness.** Model changes and reasoning-level changes
  queue visibly while a run is active and apply at the next safe request
  boundary; a Pi completion query that arrives immediately after initialize is
  served; the renderer no longer reads session history to paint.
- **Themes, selection and clipboard.** Every built-in theme the picker and CLI
  advertise is selectable by name, and app-owned pointer selection copies the
  painted transcript row across scroll, wrap and chrome.
- **Pi editors in the composer slot.** Custom Pi editors render with native
  chrome and one native slash popup; submissions use native idle/busy
  admission, and `Ctrl+G` keeps the editor mounted.
- **Python extension setup finishes.** `/extensions setup` starts the extension
  that failed cold start once its runtime is provisioned, without a restart.
- **Large-history transport.** The approved session-repair.v2 chunked transport
  replaces the legacy 512 KiB session mirror between the host and the adapter,
  with cancellable transfer and publication readiness that never depends on the
  negotiated transport.
- **Release engineering.** A one-command real-binary E2E regression suite
  (`scripts/e2e/run.sh`) drives resume, long-session scroll, selection/copy,
  themes, busy slash commands, steering, follow-up, streaming typing latency
  and Pi compat on/off against a built binary with a loopback mock provider.
  The linux x86_64 packaging path was exercised locally, including a
  byte-identical repeat of the release archive.

## Added

- `scripts/e2e/` real-binary end-to-end regression suite. One command prints
  PASS/FAIL per check, and the Pi compat smoke loads three real packages from
  the extension matrix.
- Extension command argument completions in the composer, with a bounded async
  provider that never blocks typing.
- Cache warming (`off`, `streaming`, `idle`) with `/cache-warming`, and
  inference measurements that separate server-reported timing from billing.
- Tern native rendering of the transcript, composer and context meter
  (`--tern auto|on|off`).
- `docs/releases/v0.9.0.md` and the package-local copy the TUI `/changelog`
  bundles.
- `scripts/bench-agent-loop.py`, a loopback mock-provider benchmark of agent
  overhead (startup, tool scheduling and loop rounds) for octet, Pi and
  opencode.

## Changed

- The workspace, crate pins, first-party bundle manifests, SDK distribution
  versions, the checked-in installer and the release tests move to 0.9.0.
- The interactive TUI starts fullscreen by default; `mouse = "auto"` or
  `--mouse auto` keeps inline native scrollback.
- Release notes and installation guidance keep the candidate source version and
  the published channels distinct. Binary publication requires successful CI
  for the exact immutable source; MSVC release archives additionally require
  native runtime, terminal and extracted-artifact qualification before signing.
- Bash commands remain complete in terse mode; collapsed tool output retains
  both its head and tail. Pending steering and follow-up text preserves multiline
  content within the available composer geometry.
- Codex models use ordinary Responses with parallel tool calls, as Pi does,
  even when the account inventory prefers Responses Lite. Explicit Responses
  Lite selection in the `octet-ai` SDK keeps its serial contract.
- Under full access, the independent `bash` and `read` calls of one model
  response run together, as in Pi, and their output still streams live. File
  changes, extension tools and anything that could ask for approval stay one at
  a time, and results reach the model in the order it asked.
- Removed native Search, including its schema, registration and SDK exports.
  The core tools are `read`, `edit`, `write` and `bash`; content search uses
  `rg` through `bash`. Still keeps **Explored** groups and Ctrl+O disclosure.
- `--enable-extension` saves the extension to `enabled_extensions`, like Enable
  in `/extensions`, so the menu and `/reload` stay usable. A trusted project or
  `OCTET_EXTENSIONS` activation list keeps the flag to that invocation.

## Fixed

- Pi images (including nested `ctx.executeTool` results) work on the real host,
  and `agent_settled` fires once after `agent_end`.
- Pi footers and widgets can ask whether the active model uses OAuth; the host
  answers from its authentication resolver without reading credentials, and
  unclassified resolvers refuse instead of guessing.
- Pi ordered-hook cancellation follows real callback settlement, and
  `ctx.newSession`/`ctx.switchSession`/fork commit parent linkage and writable
  setup against the replacement session.
- `/theme <built-in name>` shares the picker/CLI resolver; pointer hit testing
  matches the rendered viewport.
- The native linux packager no longer demands that tracked private workstation
  records (`docs/rc/…`) appear in the public documentation inventory.
- The adapter implements the missing Pi 1.0.2 module surface and no longer
  crashes the extension process on the real-package matrix paths.
- The inherited checkpoint failures are repaired: extension hook/lifecycle
  delivery, the MCP bridge host-access replay check, Pi session replacement,
  activity/steering PTY contracts, headless before-prompt tool snapshots and the
  API 0.1 conformance wire, plus the inherited clippy lint debt.

## Known limitations

- **Native-backed Pi editor is phase 2.** Pi's editor suites are preserved as an
  upstream test corpus, and custom editors render in the composer slot, but a
  native-backed editor facade with synchronous native editing operations and
  full upstream editor parity are not implemented.
- **Pi compatibility is a bounded sample, not parity.** The recorded
  2026-10-06 matrix of 34 real packages has 7 passing, 12 failing with
  Octet-side errors, 11 needing prerequisites the test machine did not have, and
  4 that are not extension factories. Later adapter repairs have not been
  re-measured against that matrix. See
  [compatibility](../pi-compatibility.md) and the
  [27-row ledger](../pi-extension-api.md).
- **Not qualified as a release.** Local macOS build, PTY and extension-startup
  evidence covers a pre-freeze candidate, not the final immutable release source.
  Exact-source hosted CI and release-artifact qualification remain outstanding.
  Windows GNU CI is not evidence for the MSVC release executable. Local packaging
  checks are unsigned dry runs, not signing or public-install verification.
- **Physical presentation is not measured.** The E2E suite observes the
  terminal buffer, mouse wire coordinates and OSC 52 payloads; it makes no
  claim about GPU frame presentation or end-to-end display latency.
- **Live provider and audio acceptance is not run.** The suite uses a loopback
  mock provider; no paid provider, subscription or live model is exercised.
- **Deeper compatibility surfaces remain unqualified:** exact tool-execution
  boundary parity, native-to-Pi live theme synchronization, and full
  presentation qualification for remote Pi components.
- **No performance comparison is published.** Historical pre-rename measurements
  in [benchmark evidence](../assets/evidence/README.md) are not octet results.
