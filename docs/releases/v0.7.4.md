# octet 0.7.4 — UNPUBLISHED source candidate

**This is not an available release.** The latest published release remains
[0.7.3](v0.7.3.md). No v0.7.4 tag, signed assets, registry publication or public
installation is claimed. Public installation commands remain pinned to v0.7.3.

## Candidate scope

- Product, SDK, Serve, installer/image sources and the four official executable
  bundles are aligned to distribution version 0.7.4. Candidate bundles require
  exactly octet 0.7.4; use a matching local build and reviewed local archives.
- Extension APIs 0.1/0.2/0.3, native-host protocol 1, independent schema revisions
  and example versions are unchanged. Installation never enables extensions.
- Maintenance #411 is already merged, including #403, #357, #208, #201 and #361.
  This candidate does not represent those maintenance changes as pending merges.
- The three medium-severity GitHub Vitest alerts are fixed on main.
- Custom-provider startup discovery now overlaps independent foreground jobs
  in batches of at most four, preserving registry order, validation and caches.
- Provider-usage reconciliation avoids whole-branch reference allocation for a
  recent measurement and immediately skips empty usage ledgers. Full context
  estimation and usage-ledger lookup are not constant-time.
- [Scoped local performance evidence](../benchmarks/v0.7.4-performance.md)
  retains matched trials and limitations; no live-provider or end-to-end
  startup speedup is claimed.
- ANSI256 Light added-diff markers retain green semantics with improved contrast,
  plus confirmation/outcome geometry regressions. This does not close #382.
- Qualified Codex interrupted inference is replaced within bounded recovery,
  with independent, cancellable pre-send network waiting. Completed tool work
  is retained rather than replayed; auxiliary operations use their own recovery
  status and controls remain host-owned.
- Failed-attempt usage uncertainty is durable across resume and branch checkout.
  Known usage/cost subtotals are explicitly distinguished from complete totals;
  unresolved exposure prevents enforcing a hard cumulative ceiling.
- Additive recovery events, hook context and `usage_uncertainty` session records
  evolve their contracts without changing their independent version numbers.

## Recovery qualification — OPEN

The [recovery qualification note](../qualification/v0.7.4-recovery.md) compares
source behavior with pinned Codex and separates deterministic fault injection
from live-provider and actual endurance evidence. Full #350/#346 acceptance is
not claimed. Passing held-API PTY tests does not establish physical terminal
acceptance or explain every reported freeze. The latest recovery edits require
fresh frozen-source review and CI; earlier candidate checks do not qualify them.

## Mandatory release gate — OPEN

**#382 physical terminal acceptance is UNRUN.** Deterministic tests, PTY fixtures
and code review do not substitute for physical visual acceptance. The required
Terminal.app, Ghostty and Ghostty-to-Ubuntu SSH matrix must record actual
observations for the requested widths, colour modes, selection/copy, streaming
and completion behavior. Do not infer a pass from automated renderer coverage.

Publication remains blocked by physical acceptance. No 0.7.4 release/tooling
tags, signed assets or public installation are claimed. Separately reviewed code
merges do not establish release qualification.

## Verification and publication handoff

Final frozen-source CI checks and physical acceptance remain mandatory.
Local runtime correctness and matched measurements are documented separately.
Metadata/extension/installer checks are local candidate checks, not evidence of
signed publication or public installation.

Publication requires all mandatory gates to pass, an authorized canonical
release commit, and exact-version native and Serve assets and all four bundles.
Public commands and release-availability labels remain unchanged until signatures
and public installation are verified. The source installer already targets
0.7.4, but is candidate release tooling, not an installation route before
publication. The image script requires a clean tracked source commit.

npm, Homebrew, crates.io and SDK registries remain separate unpublished channels.
Serve remains experimental. Historical release evidence belongs to its original
version; it is not carried forward as a new pass.
